# 周末盲盒 Agent 的执行约束

参考 edu-agent 的“模型提出，程序决定”：模型只理解需求，程序负责执行与核对。

1. 仅支持同城、同一天、1–6 人。每个人有主动提供的出发地与空闲时间，不默认获得设备定位，不跨夜。
2. 信息不足先追问；预算是每人金额。记录状态只在本次页面会话中存在。
3. 取多人时间交集，并为各人集合与返程预留估算时间。预算、移动距离或共同时间不满足时不凑路线。
4. 优先返回 2–3 套完整三站路线；只有 1 套时说明，不得虚构其他选择。
5. 地图地点和活动搜索结果保留来源。地图有该场馆不代表出发当天有展；搜索命中不等于官方核实。
6. 面向本地居住者，常住城市必须由用户确认。实时服务缺失或失败时保留原城市和条件，不自动使用杭州或其他样例。样例只允许用户在设置中主动选择。
11. 设备定位仅在主动授权后用于城市、片区识别，须确认；不把云服务器 IP 所在地当成用户常住地。
12. 活动供给先校验城市、日期、来源与结构；接入高德核对场馆，再进入候选路线。资讯摘要不等于日期、票价或营业已经核实。不想再去的地点、通勤上限必须实际过滤。
7. 消费、交通时间和步行距离均为估算，地图是位置示意。未知营业、票价、预约状态明确待确认。
8. 过程仅展示真实步骤、工具状态和校验摘要，不输出内心推理或思维链。
9. 邀请函包含日期、集合地点、时间线、地址、每人费用估算和出发前确认事项。只生成，不代发，不订票，不订位，不支付。
10. 对外固定四字段 JSON：schema_version、intent、message、next_step；完整结构必须通过 response.schema.json。路线另外通过 plan.schema.json，模型提取通过 coordinator.schema.json。模型输出失败重试一次，仍失败时降级规则理解。任何失败都保留输入，给出可恢复提示。
